# 照片显示调整

能力范围是明信片里照片的呈现：透明程度、图框适配、对齐、底色和圆角；原始照片字节保持不变。宿主用自然语言理解请求，脚本只执行已验证的参数，不识别人物、自动裁切主体或修改像素。

## 自然语言到显示设置

| 用户表达 | 处理 |
| --- | --- |
| 照片淡一点 | 未给数值先用 `opacity: 0.85`，即不透明度 85%，透明 15%；告诉用户本次值 |
| 透明 20% / 不透明度 80% | 均映射为 `opacity: 0.8`；不要把“更透明”误设为更高 opacity |
| 完整显示，不要裁切 | `fit: contain`；默认自然宽高；固定框比例时可能留边 |
| 铺满这个框 | `fit: cover` 并给出 `aspect_ratio`；预览会被裁掉的边缘 |
| 铺满，但人物不要被裁掉 | 尽量让框比例贴近原图，结合主体位置调对齐；不满足时优先人物完整并说明取舍 |
| 把可见区域移向照片右边 | 调高 `position` 的第一个数值，例如 `[70, 50]`；需有实际可裁切的余量才有效 |
| 照片圆角一点 | `radius: 16`；仅作用于照片框，预览四角是否遮住重要内容 |
| 恢复原图效果 | `opacity: 1`、`fit: contain`、`position: [50,50]`、`radius: 0`，省略 `aspect_ratio` |

“人物靠右一点”不是机械增加 position：cover 的 position 控制保留原图的哪部分，不是把人移动到哪里。先看裁切轴与可见范围，预览后决定；必要时改照片区域的排布。没有裁切或留边空间时，调位置可能看不出变化，要说明而非假称成功。

## 内容 JSON 可选字段

在原来的文案 JSON 上增加一个 `photo` 对象即可：

```json
{
  "photo": {
    "opacity": 0.85,
    "fit": "contain",
    "position": [50, 50],
    "aspect_ratio": [4, 3],
    "background": "#F7F3EA",
    "radius": 16
  }
}
```

这只是新增字段示意，不是完整输入；保留 title、caption、recipient、story、wish、photo_alt 等原有字段。脚本调用命令不变，也支持任意兼容的 `--template`。

| 字段 | 范围与默认值 |
| --- | --- |
| opacity | 有限数值 0～1，默认 1；0 完全透明，1 完全不透明 |
| fit | contain（默认）或 cover；不提供会扭曲人物的 fill 拉伸选项 |
| position | `[横向百分比, 纵向百分比]`，各 0～100，默认 `[50,50]` |
| aspect_ratio | `[宽,高]`，正有限数值，各 0.01～1000；省略时随原图自然比例；cover 时必填 |
| background | 六位十六进制颜色，默认 `#fff9ee`；透出的衬底及留边颜色 |
| radius | 圆角像素，0～80，默认 0 |

不提供 `photo` 时保持现有模板行为，不影响旧输入。提供后脚本构造独立照片框和经过验证的内联 CSS，覆盖模板中图片的固定高度；无需新增模板变量，也不将整个明信片设为透明。自定义模板不应再给照片祖先设置冲突的 opacity、滤镜、定高裁切或 `!important` 图片样式。

## 预览与交付

- 对比修改前后，确认只改变请求的照片效果，正文仍完整且对比清楚。
- cover 会裁切；检查桌面和手机上的脸、头顶、手、肢体与重要景物，区分原图本就未拍全的部位与新增裁切。不能靠 object-position 自动保证保留主体。
- 比例与位置变化不需要改写 `photo_alt` 中的原始事实；成品中若某细节不再可见，应避免用它描述当前可见图像。
- 不透明度与底色共同决定视觉效果，不是给照片增加新天气、时间或滤镜事实。
- 生成新 HTML，旧成品和原图保留。照片没有嵌入或不可读时，不声称调整已生效。
- 无浏览器时只报告生成的参数与静态检查，明确显示效果尚未视觉验证。
